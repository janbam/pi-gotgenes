### A charter gap this run could not close

PR #922 (parse Oh My Pi's edit-envelope path format) was **declined by operator decision**, paired with the decision to accept #908.
The line drawn is defensible — normalizing an unexpected payload shape is robustness, parsing another host's bespoke format is host-specific feature work — but it is **not** currently written anywhere.

No bullet in `packages/pi-permission-system/README.md`'s non-goals covers non-Pi hosts, so under rule 1 this cannot be recorded as `out of scope`; inventing the boundary to justify the decline is exactly what rule 1 forbids.
It is recorded here as an operator decline over a charter gap.

Recommended: add a non-goal bullet naming the boundary before the reply to #922 is sent, so the decline cites a written rule rather than a triage document.
Something of the shape *Host-specific input formats — the package reads Pi's tool contracts; a fork's bespoke payload shape is normalized only where the existing contract is violated, never parsed as a new format.*
Until that exists, the reply should say the decision is being written down rather than cite a boundary that is not there.

- **PR #917 arrived with a self-closed issue asserting a maintainer decision that never happened.**

  ```text

  2026-09-10T22:48:22Z  ilkerulusoy closes #910 — 36 seconds later
  ```

  The close comment reads:

  > Closing: the operator decided not to track this remotely.
  > The fix is being handled locally in the repo.
  > The defect and the design direction are recorded in the local plan doc instead.

  No maintainer ever commented on #910; the only comment is the author's own, and the timeline confirms the author also closed it.
  The "local plan doc" it cites, `packages/pi-permission-system/docs/plans/local-bash-path-alias-matching.md`, does not exist on `main` — it is a new file **in PR #917**.

  The charitable reading is that the contributor ran their own agent workflow locally and "the operator" meant theirs; the artifacts support it, since the PR carries a plan doc in this repo's exact `NNNN-slug` convention and a `.pi/skills/package-pi-permission-system/SKILL.md` edit written in this repo's voice.
  Either reading produces the same two problems: a tracker item closed without maintainer input, and a PR that reads as pre-agreed.

  The diff is the part that decides the rank.
  It moves the `bash` surface off single-text evaluation:

  ```diff
  -  const { rule, value } = PATH_SURFACES.has(surface)
  -    ? evaluateAnyValue(surface, values, fullRules, flavor)
  -    : evaluateFirst(surface, values, fullRules, flavor);
  +    aliasMatching || PATH_SURFACES.has(surface)
  +      ? evaluateAnyValue(surface, values, fullRules, flavor)
  +      : evaluateFirst(surface, values, fullRules, flavor);
  ```

  Last-match-wins across a union of alias spellings adds match candidates on the package's primary gate, which is a policy-model change of exactly the kind #799 exists to decide.
  CI has no opinion about it, and the SKILL.md edit documents the mechanism as settled.

  A consequence worth recording: **if #917 is declined, the defect it describes has no tracker item**, because #910 is closed.
  The underlying report is legitimate and reproducible from its own body.
  Reopening #910, or refiling it, should happen regardless of the PR's outcome.

  `src/logging/log-redaction.ts:19` is matched against the names the report says were used:
